🔒 Security notes

  • Access: only emails listed in ADMIN_MAIL can sign in — login runs through Google, there's no password anymore.
  • Delivery: loadstrings reference a random, rotatable public id — never a filename or the script content — resolved server-side through /api/loader/<id>, with rate limiting and an enabled/disabled flag checked on every request.
  • Rotation: hitting "Rotate link" on a script issues a new public id and immediately invalidates the old one, so a leaked or over-shared loadstring can be cut off without deleting the script.
  • Source protection is still limited: a Lua script loaded via loadstring in an executor has to arrive on the client as runnable code. Anyone running it through an executor can, in principle, capture what it loads — no web technique changes that once the request is authorized.
  • What does NOT exist: a trick that allows execution but makes reading completely impossible. What's implemented here reduces exposure and makes abuse easy to shut off — it isn't a guarantee, and destructive anti-analysis tricks (crashing/freezing the client) are deliberately not used.
